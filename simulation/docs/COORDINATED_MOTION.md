# 五关节协同路径搜索

当前默认流程：土面位置和腕姿搜索 → 不同侧向通道 → 加权 RRT* → 接触代价优化 → 整条轨迹的关节协同搜索 → MuJoCo 动态复查 → 轨迹线和动画。

`scripts/coordinated_motion.py` 在已经可行的路径上搜索三类候选：

- 五个关节独立的单调进度曲线，使转腕、抬肘和转肩可以提前或延后。
- 整条轨迹的平滑关节偏移，同时调整多个路点，而非只动一个点。
- 喷口位置雅可比的零空间姿态变化，尝试在基本保持喷口位置的情况下调整肘腕姿态。逐个路点的位置误差需小于 0.25 mm，路点之间仍重新检查。

SO-101 使用五个机械臂关节。夹爪开合角保持固定以握住喷嘴；不把开合伪装成额外旋转自由度。起点、终点和土面目标保持不变。

## 选择规则

配置文件为 `configs/coordinated_motion.json`。

`selection_mode=coordinated` 表示用户指定的协调运动偏好：在通过密集复查的候选中，先求最低连续接触代理代价 Cmin，只允许代价不超过 1.15 × Cmin、且不超过原基准路径代价的路线。时长不超过该最低代价路线的 1.65 倍，总关节角行程不超过 2.4 倍。随后优先选各关节参与更均衡的路线。Cmin 为零时不允许增加接触。15% 是可调的协调偏好预算，不是物理损伤容许量。

协调评分使用各关节角度范围相对于 [20,30,30,35,45] 度的比例，并在 1 饱和；综合平均值和最小值，扣除多余往返行程。无休止绕圈不会持续增加评分。这些数值是搜索偏好，不是每个关节必须达到的动作要求。

`selection_mode=efficient` 只选择原来的 `连续接触代价 + 0.05 × 时长` 最低候选。两种模式都保留候选分数、基准分数和实际取舍；不能把为了展示而增加的动作称为全局最优或损伤更低。

原有叶片/花朵中心与尺寸权重、枝干权重、0–5 mm 非线性距离倍率和连续接触累计规则继续参与评分。花盆、泥土、小车、地面、机器人自身和工作空间约束仍必须通过检查。代价是几何接近/接触代理，不是测得的损伤或力。

## 验证与结果

粗时间采样仅筛选候选。入选路线还需通过密集关节空间检查和 40 ms 时间评分；后续 `validate_watering_trajectory.py` 检查实际 actuator 运动、跟踪误差、硬障碍间隙和末端土面约束。只有 `SAMPLED_REPLAY_CHECKS_PASSED` 才可作为本次采样验证通过的结果。

`coordination_report.json` 保存全部设置、基准、搜索数量、拒绝原因及选择取舍。`path_report.json` 保存每个关节的运动范围。`nozzle_path_line.csv` 为以米计的喷口轨迹；回放目录中的 `nozzle_path_line.png` 和 `trajectory_replay.gif` 显示实际仿真运动。

服务器入口 `scripts/run_server_job.py` 在 `06_attitude` 后增加 `06b_coordination`，随后执行原有动态复查和渲染。项目配置 `configs/plant_pipeline.json` 的 `simulation_coordination_config` 指向该配置；删除该键可使用原流程。更新代码后旧结果不会自动改变，必须运行新规划。已经完成任务的签名变化仍按原有规则处理，不能篡改签名假装旧任务已使用新代码。
