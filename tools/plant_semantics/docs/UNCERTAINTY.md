# v3 最终不确定标记复核

默认主线使用 GroundingDINO-Tiny、CLIPSeg 和 MobileSAM。已有证据复核阶段不加载模型；后述 0.2.4 新视角复核会使用原三个模型。两者均不调用 SAM3，不下载资产。

## 为什么要复核

原五类阶段中，早期 label=0、观测不足或分差低都会触发 `uncertain`。此后叶面修复保留历史标记，窄叶缘补全也将新增点标为不确定。因此它记录了处理历史，不能直接当最终错误比例。

新步骤依据现有最终证据解除一部分历史标记，分类和几何保持原样。仍保留真实证据不足或冲突的点，不以把比例降至某个目标为目的。

## 解除条件

首先，最终赋类必须与分数最大类相同，赋类分数 ≥0.65、前两类分差 ≥0.30。这些是启发式分数，不是正确概率。仅凭分数很高不能解除标记，还必须符合以下至少一组独立证据：

1. **器官实例证据**：至少 3 个不同主相机观测并支持当前类；支持比例 ≥0.70，比最强竞争类的支持比例领先 ≥0.20，累计实例证据除以支持相机数 ≥0.15。同一主相机的局部裁剪不会重复计票。
2. **叶面掩膜证据**：当前类为叶片、不是受保护花苞，至少 3 个不同相机的自动叶面掩膜支持，同意率 ≥0.70。它可解决早期器官检测与完整叶面之间的分歧。

仅由窄叶缘几何规则改过的点，必须有上述叶面掩膜独立确认，不能仅靠器官实例证据解除标记。

只解除已有历史标记，不把原来未标记的点新增为不确定。它是历史标记复核，不是全新、校准后的分类置信度系统；原始分类仍可能有高置信错误。阈值为工程选择，尚无人工真值校准。

## 保存字段

| 字段 | 含义 |
| --- | --- |
| `uncertain` | 复核后仍需关注的点 |
| `uncertain_before_reassessment` | 完整保留输入 v3 的标记 |
| `uncertainty_released` | 本次解除标记的位置 |
| `uncertainty_semantic_confirmed` | 通过器官实例证据与最终分数复核的历史点 |
| `uncertainty_leaf_confirmed` | 通过独立叶面掩膜与最终分数复核的历史点，可与上一项重合 |
| `uncertainty_reason` | 保留原因位掩码，详见输出 `uncertainty_config.json` |

`inferred`、`propagated_unobserved` 等历史属性保持不变。输出还包括原输入与证据哈希、逐类数量、标记对比图及逐字段不变性审计。源目录保留，可恢复原始规则。

## 使用

完整入口 `run_auto.ps1` 自动执行。若已有 v3 结果，可单独复核：

```powershell
python reassess_uncertainty.py `
  --source 'F:\植物建模\outputs\plant_semantics_complete_v3' `
  --instances 'F:\植物建模\outputs\plant_semantics_complete_v1' `
  --output 'F:\植物建模\outputs\plant_semantics_complete_v3_reviewed'
python validate_complete.py `
  --input 'F:\植物建模\outputs\Plant_cropped.ply' `
  --output 'F:\植物建模\outputs\plant_semantics_complete_v3_reviewed'
```

`--instances` 指向该输入对应的五类阶段缓存目录，包含 `instance_vertices.npz`、`instance_config.json` 和 `inference_config.json`。对新模型自动输出，它是 `complete_before_boundary/`；原植物的历史名称为 `plant_semantics_complete_v1`。程序核对输入、相机路径、观测数及缓存身份，不支持用 SAM3 缓存替代。

## 本株结果与机器人用途

| 当前分类 | 原标记 | 解除 | 剩余 |
| --- | ---: | ---: | ---: |
| 茎枝 | 57,607 | 2,866 | 54,741 |
| 叶片 | 110,283 | 75,542 | 34,741 |
| 花/花苞 | 284,984 | 390 | 284,594 |
| 盆/托盘 | 11,031 | 921 | 10,110 |
| 基质 | 13,167 | 6,266 | 6,901 |
| 合计 | 477,072 | 85,985 | 391,087 |

总占比从 30.43% 变为 24.95%。基质共有 17,541 个顶点，剩余 6,901 个标记（39.34%），10,640 个无该标记。数量随三角面密度变化，不能等同于表面积、错误面积或浇水区域面积。

无标记不证明分类正确或机器人可安全到达。浇水落点仍需检查盆内范围、真实尺度/坐标标定、水流通道、机械臂全身碰撞及可达性；所有实体表面继续作为碰撞对象。若要大幅降低剩余标记，通常需要新增可见视角证据或改进表面观测，不能仅调小阈值。

## 0.2.4：可选新增视角复核

这是独立的后续步骤，会运行原 v3 的三个模型。它不调用 SAM3，也不改标签或分数；默认 `run_auto.ps1` 不自动追加本步骤，以免每次都增加推理开销。

### 选择与推理

1. 从方位角 30/90/150/210/270/330 度、仰角 -50/-15/30/65 度生成 24 个候选相机。
2. 射线检查原始顶点的实际遮挡；只围绕当前不确定点统计覆盖，按每点对应表面积计权，并逐类归一。茎/叶/花/盆/基质的覆盖优先系数为 1.5/1/1/0.5/2.5；不是机械臂路径权重。
3. 贪心选择覆盖收益大的相机，重复覆盖收益递减，该选择阶段相机间至少相隔 25 度。预算 ≥6 且存在不确定基质时，额外补足方位角 30/150/270、仰角 65 度的三个俯视角；融合前检查最终相机间隔至少 20 度。因此实际相机数可比 `Views` 多，最多仍为候选集的 24 个。本株预算 12、实际 14 个。
4. 用与原始 v3 完全相同的权重、文本和推理规则预测每张新图。逐顶点投影与深度检查，每个新相机对一个点最多投一票；同图裁剪不累计票数。程序验证模型、推理与源数据哈希，缓存不匹配时报错。

这些是已有 RGB 网格的渲染方向，不是新增真实照片或扫描数据；看不到的缺失表面无法凭渲染补出。相机方向分散也不意味着统计独立，同一模型的误判可能重复。

### 更新条件

解除标记要求：原最终赋类是最大分数类、分数 ≥0.65、前两类分差 ≥0.30；新增相机中至少 3 票支持该类，同意率 ≥0.70，比最强竞争类票数占比领先 ≥0.30；该类累计新证据除以新可见相机数 ≥0.20。所有实际观测，包括弃权和竞争类，都计入分母。旧相机不与新票数混合来满足“至少 3 票”。

若最强竞争类获得至少 3 个新增相机支持、占全部新增可见相机 ≥0.70 且领先原赋类 ≥0.30，会新增或保留冲突标记。即使这样会增加某一类的不确定数量，也不忽略冲突。不会据此自动改标签；竞争共识也可能来自模型错误，应单独检查。

### 运行与字段

```powershell
& 'F:\植物建模\tools\plant_semantics\run_extra_views.ps1' `
  -SourceDirectory 'F:\植物建模\outputs\plant_semantics_complete_v3_reviewed' `
  -OutputDirectory 'F:\植物建模\outputs\plant_semantics_v3_extra_views' `
  -Views 12
```

入口执行 `prepare → predict → apply → validate_complete`。支持 `-Size`、`-Threads`、`-Device`、`-PythonExecutable`、`-SamCheckpoint`。底层 Python 可单独运行各阶段；自定义权重必须与源结果一致。源目录必须保留其 `manifest.json` 所指向的原始模型及 base 配置。使用独立输出目录；同配置可从缓存恢复。改变相机预算时仍从同一源结果开始并使用新目录，不把已复核结果再作为输入。

新结果位于 `complete/`，新增字段为：

| 字段 | 含义 |
| --- | --- |
| `uncertain_before_extra_views` | 新增视角之前的当前标记 |
| `extra_view_released` | 本步骤解除的历史标记 |
| `extra_view_conflict` | 新增视角发现的竞争类强共识，包含原来已标记的点 |
| `extra_view_confirmed` | 新视角与原分数共同确认当前类的位置，包含原来未标记的点 |
| `extra_view_count` | 新增相机中实际可见的相机数 |
| `extra_view_assigned_votes` | 新相机对当前赋类投票数 |
| `extra_view_agreement` | 当前类票数 / 新可见相机数 |

`extra_view_report.json` 是本步骤的数量报告；`extra_view_audit.json` 检查除当前 `uncertain` 外全部原 NPZ 字段不变；`extra_view_config.json` 记录规则与身份。输出根目录保留新相机清单、渲染、二维预测及 `extra_evidence.npz`。新图 `uncertainty_comparison.jpg` 比较本步骤前后，复制的 `uncertainty_report.json` 等文件仍描述上一步，不能当本步骤最终数量。

### 本株实测

| 当前分类 | 加视角前 | 解除 | 新增冲突 | 加视角后 |
| --- | ---: | ---: | ---: | ---: |
| 茎枝 | 54,741 | 187 | 5,940 | 60,494 |
| 叶片 | 34,741 | 121 | 1,025 | 35,645 |
| 花/花苞 | 284,594 | 71,751 | 3 | 212,846 |
| 盆/托盘 | 10,110 | 3,314 | 0 | 6,796 |
| 基质 | 6,901 | 102 | 472 | 7,271 |
| 合计 | 391,087 | 75,475 | 7,440 | 323,052 |

总比例 24.95% → 20.61%，净减少 68,035 个（原剩余标记的约 17.40%）。从最早 v3 的 477,072 个历史标记到本结果，净减少 154,020 个。实际减少主要是花瓣背面获得新增观测，并非细茎与盆内都已改善。对后续浇水用途，更应检查基质的冲突和盆口局部图，而不是追求全株标记百分比。

新增局部放大视图、针对盆口的近距离观测以及补拍真实遮挡区域，可能进一步提供有效信息；这些尚未在本步骤实现。简单增加相近全局相机的收益会递减，不能保证越多越准。
