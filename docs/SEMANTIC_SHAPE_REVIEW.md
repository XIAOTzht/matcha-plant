# 叶片 / 枝干 / 整花复查

图片中的错误来自上游语义标签；权重和器官实例继承它，因此不能靠改显示颜色解决。

更新采用 GroundingDINO + MobileSAM 独立提出 RGB 器官掩膜，再用 CLIPSeg 作弱辅助，
从 24 个方向检查。4 个平视方向各有 4 个重叠局部放大视图；同一方向所有裁块只算一票。
基础识别补充 flower / flower head / flower center；复查使用更具体的 flower head /
flower bloom / flower seed head，以及 plant leaf / dried leaf / leaf blade，
避免泛词将整束植物算作花、将浅色叶片算作花瓣。

复查 2.0 将枝干、普通叶片、卷曲/干叶、整花分成独立文本组检测，
减少长句中类别互相抑制导致的漏检。不同文本组和同方向裁块仍合并成一票；
增加同义词不会人为增加支持方向。单叶和单花都拒绝覆盖整束植物的过大掩膜。
CUDA 默认使用混合精度推理以减少显存峰值，CPU 使用 float32；可显式指定
`--precision float32`。精度选项写入复查配置，不能跨配置混用证据。

对每个掩膜计算三维长宽、厚薄和多尺度局部 PCA。宽片形且缺少细长结构的掩膜不能提供
枝干证据。形状只作辅助，圆叶、窄叶、花瓣没有固定几何边界；绝不将“黄色=花”、
“不绿=枝干”作为规则。不使用当前植物的手选坐标、器官数或向日葵专属阈值。

修改需至少 3 个方向支持、有效识别方向中至少 75% 同意，并满足证据强度和领先幅度；
原类别分数 >0.95 时至少 4 个方向、80%。没有检出的方向表示缺失证据，不作反对票。
这些是启发式分数，不是准确率或概率。
花盆、泥土、小车及原 unknown 保持不变。所有改动点保留不确定标记；原标记不会清除。

多视角种子可沿真实网格边补全短距离碎块：只处理叶/花，RGB 差异增加传播代价，
细长管状结构阻断传播，最长传播范围为场景尺度的 2.5%，且目标点自己至少需一票。
不连接空间上相近但网格未连接的器官；竞争类别距离不明确时保留原标签。

2.0 在这些独立证据后新增表面一致性优化：将实际相连的细小网格单元合并，
最小化“表面积加权分类证据 + 表面类别边界代价”的 Potts 能量，使用 alpha-expansion
求近似解。RGB 边界降低相邻区域合并倾向；细长枝干有额外保留证据。该步骤允许器官内
缺少逐点票数的小碎片随完整叶面修正，不能把此后每一个顶点都称为独立多视角确认。
它不跨越未连接网格、不改花盆/泥土/小车/unknown，但重建粘连仍可能造成错误合并。
`surface_consistency_report.json` 记录参数、改动量及逐步下降的能量。

表面一致性 1.1 进一步检查残留枝干：两个尺度都缺少细长性、同时呈片状的表面，
其枝干代价随片状程度连续增加（最高加 0.90 的启发式代价）。这只降低“片状=枝干”
的倾向，不直接将片状命名为叶片；叶/花仍由独立 RGB 掩膜证据和真实网格邻接决定。
两个尺度有足够细长性且低平面性的旧枝干加保留证据，容许弯曲，不能按整根必须笔直判断。
完全没有叶/花投票的独立网格组件不应用此惩罚，避免无观测时凭类别顺序猜标签。
不使用手选坐标或当前植物颜色阈值；对重建粘连和遮挡严重的部位仍需检查。

1.2 增加叶缘/花瓣卷边复查：在真实网格上，以已有叶/花宽片表面和 RGB 掩膜票为种子，
计算表面扩散支持及同一表面邻域的形状。卷边虽然局部细长，若沿其长度连接着宽片表面，
较大表面邻域会表现出片状；真正离开叶面延伸的枝干则继续呈细长结构。
仅修改残留的枝干标签；已有叶/花、花盆/泥土/小车/unknown 不在此步骤改动。
需满足叶/花支持占比 >0.16、类别一致性 >0.80、表面邻域线性度 <0.65，
并且沿原始网格的 RGB 加权距离不超过植物尺度 1.5%；至少两票且占优的枝干证据保留。
质量矩阵按表面积、导通按双边长度/原边长度计算，扩散距离随场景尺度变化。
此规则不会连接未相连网格，或根据截图手选点；粘连网格和真实叶柄连接处仍可能混淆。
`stem_rim_report.json` 记录边缘修订数量及参数；NPZ 的 `stem_rim_changed` 保留逐点记录。

权重进一步使用平滑闭合轮廓的距离场、连续采样及 smoothstep，中心高、边缘低。
完整叶/花的不确定加权改为该器官“不确定表面积占比”对应的单一倍率（1 到 1.2），
原逐点不确定标记仍保存。这样不再因每个小三角形的标记切换而产生权重棋盘格。
枝干和未解决碎片仍按原规则保守处理；不同真实器官之间不混合权重。

输出保留原顶点、三角形、毫米坐标、原始 RGB；重新读取 PLY 验证其与 NPZ 一致。
历史标签与分数另存于 NPZ，报告列出每种类别转换。验证 PASS 仅证明文件一致性；
真实语义效果需要查看 `semantic_comparison.jpg` 和 `views/*_mask.jpg`。
`semantic_surface_comparison.jpg` 使用遮挡正确的表面渲染，三列为原始 RGB、
修正前、修正后，并包含下方花盘的近景；建议优先查看这张图。

## 现有成功模型

先在 Windows PowerShell 上传代码：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "F:\plant\matcha_plant\maintenance\upload_plant_pipeline.ps1"
```

再在 Windows PowerShell 启动独立复查：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "F:\plant\matcha_plant\maintenance\start_semantic_review.ps1" -RunName "plant_20261106_new" -Revision "plant_20261106_new_shape_v1"
```

默认重做语义、分花叶和权重，不重建、不覆盖旧成功结果。新输出位于服务器：
`outputs/semantic_refinement/plant_20261106_new_shape_v1/`。
脚本显示日志绝对路径；在服务器用 `tail -f` 查看。
确认新语义后再规划；首次启动加 `-Plan` 会连同新权重重新搜索路径和仿真，
使用独立仿真任务名。已运行的同一版本需维持参数不变，可用 `-Resume` 续跑；
改变代码或 `-Plan` 参数时另选 revision，禁止绕过签名重用旧路径。

结果目录的 `SEMANTIC_REVISION_EXPORTED` 表示复查/权重导出完成，
`result_paths.json` 给出模型、对照图及路径是否重新生成。
`REVISION_FAILED.json` 表示失败；不要仅凭 tmux 退出判定成功。

若要先在本地验证，运行 `maintenance/fetch_semantic_review_inputs.ps1` 补齐服务器原始
RGB 和配套标签。以前下载的 semantic_mesh 是语义配色，不能当成原始 RGB 输入。
